`nylon-lb` gives Services of `type=LoadBalancer` real, reachable addresses inside a nylon mesh. It watches those Services, allocates a free IPv4 address from a pool you configure, writes the address into the Service's `status.loadBalancer.ingress`, and announces the address as a `/32` into the mesh by writing a file to the [dynamic prefixes directory](/reference/dynamic-prefixes). Cilium running in kube-proxy-replacement mode consumes `status.loadBalancer.ingress` and steers traffic to the Service.

`nylon-lb` owns no datapath. Forwarding happens in the node's existing network stack; the controller only allocates addresses, and the speaker only makes the mesh aware of them.

## Architecture

One binary contains two components that you can enable and disable independently:

- **Allocator** — runs once per cluster. It watches Services only, picks the lowest free address from the Service's selected pool for each LoadBalancer Service, and writes it to `status.loadBalancer.ingress` with single-object compare-and-swap updates. The allocator runs under leader election with a Lease named `nylon-lb-allocator`; the CAS status writes keep a partitioned ex-leader from corrupting anything.
- **Speaker** — runs on every node. It watches Services and EndpointSlices, which is why `/readyz` waits for both informer caches to sync; for each Service the node should announce, it binds the allocated address to the loopback interface (Linux netlink) and writes an announce file into the prefixes directory. Speakers are never leader-elected: every node announcing the same `/32` is the design, and Babel treats the copies as anycast.

## Command-line flags

| Flag | Default | Description |
| --- | --- | --- |
| `--pool` | required | Named IPv4 pool to allocate LoadBalancer addresses from, as `name=cidr` (e.g. `shared=192.0.2.0/24`). Repeat the flag for each pool. |
| `--exclude` | none | Excludes addresses from the pool. Repeat the flag as needed. |
| `--lb-class` | none | `loadBalancerClass` to claim. Empty claims all `type=LoadBalancer` Services; set it to scope nylon-lb to its own class and coexist with other LB controllers. |
| `--prefixes-dir` | `/etc/nylon/prefixes.d` | Directory the speaker writes announce files into. |
| `--bind-interface` | `lo` | Interface to bind announced addresses to. Set it empty (`--bind-interface=`) to disable binding. |
| `--kubeconfig` | none | Path to a kubeconfig file. |
| `--node-name` | hostname | Name of this node. Must match the Kubernetes node name for `externalTrafficPolicy: Local` to work. |
| `--leader-elect` | `true` | Leader-elect the allocator. |
| `--leader-namespace` | ServiceAccount namespace, else `kube-system` | Namespace for the leader-election Lease. |
| `--resync` | `30s` | Informer resync period. |
| `--health-addr` | `:9633` | Listen address for `/healthz`, `/readyz`, and `/metrics`. Set it empty to disable the server. |
| `--speaker` | `true` | Enable the per-node announcer. |
| `--allocator` | `true` | Enable the leader-elected IP allocator. |
| `--log-level` | `$NYLON_LOG_LEVEL`, else `info` | Log level. |
| `-v`, `--verbose` | off | Verbose logging. |
| `--json` | off | Emit logs as JSON. |

Logs are structured and carry the component name `nylon-lb`, `node=<name>`, and a module (`allocator` or `speaker`). Messages from klog (client-go) are bridged into the same log pipeline.

## Allocation rules

- nylon-lb claims **every** Service of `type=LoadBalancer` in the cluster **unless `--lb-class` scopes it**: with the flag set, only Services whose `spec.loadBalancerClass` matches exactly are claimed — unclassed Services are left pending for another controller.
- Every Service selects its pool with the `nylon.io/lb-pool` annotation. Selection is fail-closed: a Service with no annotation (`MissingPoolAnnotation` event) or naming an unknown pool (`UnknownPool` event) gets no address and stays `<pending>`; an ingress address previously allocated for it is released.
- A `spec.loadBalancerIP` set on a Service is honored when the address is free and inside the selected pool.
- Allocation picks the lowest free address in the selected pool.
- The taken set is global across all pools, so overlapping pools never hand out the same address twice.
- An `--exclude` address applies to every pool that contains it.
- The pool prefix must be at least a `/30`: the network and broadcast addresses are never allocated, so smaller pools have nothing to hand out.
- Allocation is **derived, not stored**. nylon-lb recomputes the mapping from live Services on every resync and keeps no state anywhere, so deleting a Service frees its IP unconditionally. The only residual window is announce-file withdrawal lag on a down speaker node: the stale announce file persists until that node's next resync, when the stale-announce garbage collection withdraws it. There is no collision risk, because announce files are garbage-collected together with the Service.
- Kubernetes events are emitted on the Service with a pinned, machine-readable reason vocabulary: `Allocated`, `Released`, `AllocationFailed` (the selected pool is exhausted — the Service stays pending and allocation retries with backoff until an address frees up), `BadLoadBalancerIP` (a `spec.loadBalancerIP` request rejected as outside the selected pool or already taken — a pool address is allocated instead), `MissingPoolAnnotation`, and `UnknownPool`. The reasons are stable so external tooling can rely on them.
- IPv4 only.

## Announcement semantics

### Announce files

For every Service it should announce, the speaker writes one file named `lb-<namespace>-<service>.json` into `--prefixes-dir`:

```json title="lb-default-web.json"
{"version":1,"prefixes":[{"type":"static","prefix":"192.0.2.10/32","metric":0}]}
```

The file is compact JSON plus a trailing newline. The `lb-` prefix is the garbage-collection boundary: nylon-lb removes exactly the files it owns and never touches anything else in the directory, such as `00-vip.json`.

Writes are atomic (write to a temp file, then rename). The temp file deliberately does not end in `.json`, because the nylon daemon globs `*.json` in that directory. Files whose content did not change are not rewritten, so the watcher sees no churn.

### externalTrafficPolicy

The Service's `spec.externalTrafficPolicy` decides which nodes announce:

- `Cluster` (default) — every node announces every Service `/32`. Babel treats the identical prefixes as anycast, so when a node dies, traffic simply flows to the remaining announcers. Failover is free.
- `Local` — only nodes that hold at least one ready local endpoint announce the Service. An endpoint with no `Ready` condition counts as ready.

### Single announcer

Anycast is the default because it fails over for free, but a flow that must not move — a database endpoint in the middle of `pg_basebackup`, say — is better served by one stable announcer. The `nylon.io/announce: single` annotation pins exactly one:

```yaml
metadata:
  annotations:
    nylon.io/announce: single
spec:
  externalTrafficPolicy: Local
```

With `Local` and `single`, exactly one of the nodes holding a ready local endpoint announces the Service. Each speaker computes the winner from the sorted eligible node list itself — FNV-1a 64 of `"ns/name"` modulo the list length — so no coordination is needed and no node can disagree about who wins for a given set of endpoints. Moving the ready endpoint to another node moves the announcement with it, but because the winner is an index into the eligible list, any change to that set (a node joining or leaving it) can reshuffle which node wins.

The elected node withdraws its announcement when its own direct API view is more than 30 seconds stale — an unreachable API server means it can no longer be sure it is still the only owner. For a stateful path a bounded black-hole is preferable to two announcers, so the withdrawal is deliberately fail-closed; it is lifted as soon as a probe succeeds again.

`single` requires `externalTrafficPolicy: Local`: the eligible set comes from EndpointSlices, and with the `Cluster` policy there is no node-local set to elect from. A Service with `single` and `Cluster` is announced anycast, with a warning. Any unrecognised value is treated the same way.

::::caution[Always pass --node-name]
`deploy/daemonset.yaml` exports a `NODE_NAME` environment variable but does **not** pass `--node-name=$(NODE_NAME)` in the container args. Without the flag, nylon-lb falls back to the hostname, which does not match the Kubernetes node name inside a DaemonSet pod — so with `externalTrafficPolicy: Local` no node ever matches its local endpoints, and nothing gets announced. Add `--node-name=$(NODE_NAME)` to `args` in the DaemonSet before you rely on `Local` mode.
::::

### Reconcile order

The speaker's ordering is load-bearing. It binds the address to the loopback interface **before** writing the announce file, so the address already exists on the node by the time the `/32` propagates (about 250 ms after the file lands, per the prefix watcher debounce). When withdrawing a Service, it removes the announce file **before** unbinding the address.

The unbind itself waits out a **60-second drain window**. The mesh needs a moment to converge on the withdrawal, and unbinding the instant the file disappears would black-hole flows it still routes to this node. A Service that becomes announced again during the window keeps its address: the pending drain is cancelled.

## Requirements and caveats

- **Configure every pool in every receiver.** Each pool must sit inside `dynamic_prefix_ranges` in every receiver's `central.yaml`. Receivers fail closed: announcements for prefixes outside their configured ranges are dropped. See the [configuration reference](/reference/config) and the [dynamic prefixes reference](/reference/dynamic-prefixes).
- **Scope it with `--lb-class` to coexist.** With `--lb-class` set, nylon-lb owns only Services carrying that `loadBalancerClass`, and other class-scoped LoadBalancer controllers (servicelb, MetalLB, kube-vip) may run beside it; every other controller in the cluster must also be class-scoped, and unclassed Services stay `<pending>`. With the flag empty, nylon-lb claims every LoadBalancer Service and must be the only LoadBalancer controller in the cluster.
- **IPv4 only.** No IPv6 pools.
- **Run the identical pool set on every replica.** Every replica (all DaemonSet pods or bare-binary instances) must run the same `--pool` flags with the same `--exclude` addresses; each Service picks its pool with the `nylon.io/lb-pool` annotation.

## Deployment

### Use the released image

Releases publish the controller image as `ghcr.io/arsolitt/nylon/nylon-lb`: GoReleaser tags each release with `:<version>`, and stable releases also move `:latest`. The shipped DaemonSet manifest consumes this image, so the install below needs no image build of your own; use the make targets in the next section only if you want to ship a custom image.

### Build and push the image

```bash
make image-nylon-lb
make push-nylon-lb
```

`make image-nylon-lb` builds a local, native-platform image with a plain `docker build`; only `make push-nylon-lb` builds multi-arch, via `docker buildx build --push`. The runtime image is built from `scratch` and exposes port 9633. A debug variant based on `ubuntu:24.04` is available with `make image-nylon-lb-debug`.

### Install with the shipped manifests

```bash
kubectl apply -f cmd/nylon-lb/deploy/rbac.yaml
kubectl apply -f cmd/nylon-lb/deploy/daemonset.yaml
```

`rbac.yaml` creates a ServiceAccount and a ClusterRole with get/list/watch on Services and EndpointSlices, update on `services/status`, get/create/update on Leases, and create/patch on Events.

`daemonset.yaml` runs one pod per node in `kube-system`, tolerates control-plane nodes, mounts the prefixes directory from a hostPath, and runs as root (`runAsUser: 0`) with `NET_ADMIN` — both are required for the netlink bind. The manifest sets `hostNetwork: true` with `dnsPolicy: ClusterFirstWithHostNet` (the latter keeps cluster DNS resolvable), so the speaker runs in the node's network namespace and the announced `/32`s are bound on the node's `lo` rather than the pod's — which is what makes the node answer for the addresses it announces. Cilium in kube-proxy-replacement mode steers traffic using `status.loadBalancer.ingress`. Liveness and readiness probes target port 9633.

Before you enable `externalTrafficPolicy: Local`, add `--node-name=$(NODE_NAME)` to `args` in the DaemonSet as explained in the caution above.

### Allocator-only replica

An allocator-only replica needs neither root nor `NET_ADMIN`:

```bash
nylon-lb --pool=shared=192.0.2.0/24 --allocator=true --speaker=false --bind-interface=
```

### Run as a bare binary

You can run the binary directly instead of using the DaemonSet — for example under systemd, one instance per node:

```bash
nylon-lb \
  --pool=shared=192.0.2.0/24 \
  --prefixes-dir=/etc/nylon/prefixes.d \
  --node-name=node-1 \
  --kubeconfig=/etc/nylon/kubeconfig
```

Point `--prefixes-dir` at the directory your nylon daemon watches and set `--node-name` explicitly. A speaker still needs root or `CAP_NET_ADMIN` for the loopback bind. The bind is implemented with netlink and exists on Linux only: on other platforms nylon-lb refuses to start when `--bind-interface` is set (`netlink binder requires Linux`), so pass `--bind-interface=` to run a speaker without binding.

## Observability

See [Observability](/guides/observability) for wiring these signals into your monitoring stack.

### Metrics

All metrics are exposed at `/metrics` on `--health-addr` with the `nylon_lb_` prefix:

| Metric | Type | Labels | Description |
| --- | --- | --- | --- |
| `nylon_lb_build_info` | gauge | `version`, `commit` | Build identification. |
| `nylon_lb_leader` | gauge | `node` | 1 while this replica holds the allocator Lease. |
| `nylon_lb_allocated_ips` | gauge | — | Pool addresses currently allocated to owned LoadBalancer Services (`status.loadBalancer.ingress`) — the VIPs this controller has handed out. |
| `nylon_lb_services` | gauge | — | LoadBalancer Services owned by this controller. |
| `nylon_lb_announces` | gauge | — | Desired `/32` announcements for this node, recomputed each speaker reconcile (intended, not a count of successful binds or writes). |
| `nylon_lb_allocations_total` | counter | — | Address allocations. |
| `nylon_lb_releases_total` | counter | — | Ingress clearances on type change or pool-annotation failure. |
| `nylon_lb_announce_writes_total` | counter | — | Successful announce-file sync calls, including unchanged no-op calls: it advances per desired announce per reconcile (~30 s resync) even when nothing on disk changes. |
| `nylon_lb_errors_total` | counter | `kind` | Errors by kind: `bind`, `write`, `reconcile`, `list`, `glob`. |

`nylon_lb_services` and `nylon_lb_allocated_ips` are cluster-wide: every replica derives them from the same Service informer cache and reports identical values, so aggregate them with `max`, never `sum`. Their difference is the number of managed Services still waiting for an address — a Service with a missing or unknown pool annotation, an exhausted pool, or a status write not yet observed.

Note that `nylon_lb_releases_total` does not move when a Service is deleted: once the Service is gone from the lister there is no ingress left to clear, and the stale announce file is withdrawn by the speaker's garbage collection instead.

### Health endpoints

- `/healthz` — liveness. Returns 200 as soon as the HTTP server is serving.
- `/readyz` — readiness. Returns 503 `informer caches not synced` until the Service and EndpointSlice informer caches have synced, then 200.
- `/metrics` — Prometheus text format.
